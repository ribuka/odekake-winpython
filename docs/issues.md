## 1. Python 3.12.2 そのものを同梱する

### 背景
- ユーザーは 3.12.2 を使う。理由は互換性への心配。
- 2026-10-06 の検討では、3.12 系の WinPython にある新しい版(3.12.10)を同梱することにした。表はマイナー番号(3.12)で引く。(確定)
  - パッチ番号だけが違う版は、バグ修正とセキュリティ修正だけを含み、ABI も変わらない(Python の公式方針)。
  - 3.12.2 には、そのあとのセキュリティ修正が入っていない。
- ユーザーは迷っていたので、3.12.2 そのものの同梱も選べるよう、ここに残す。

### 判明している事実(2026-10-06 確認)
- 3.12.2 の dot 版は、2024-01 リリース(タグ `7.1.20240203final`)にある。
  - URL: https://github.com/winpython/winpython/releases/download/7.1.20240203final/Winpython64-3.12.2.0dot.exe
  - SHA-256: `50438ca67201125b4be2c278741864b2d40aaeb403849b7abd1805c819e89473`(https://winpython.github.io/md5_sha1.txt による)
  - サイズ: 24,295,793
- .exe しかなく、.zip はない。
- GitHub API の digest がない。SHA-256 を確かめられる公式の情報源は `md5_sha1.txt` の1か所だけ。

### 対応する場合に必要なこと
1. .exe の展開処理を足す。自己展開型の 7z と思われる。(推測) 7-Zip を使うか、.exe 自身に展開させるかは、試して決める。
2. 中のフォルダ構成を確かめる。`python\python.exe` と `python\Lib\site-packages\` の深さ、`._pth` の有無、同梱の pip の版。(未検証)
3. SHA-256 を2か所で確かめる決まり(spec §5)を、この版だけゆるめるかどうか。(未決定)
4. 表の引き方を、パッチ番号まで一致する行を探す形に変える。`.python-version` が `3.12` だけのときにどの行を使うかも決める。(未決定)

### 関連
- 3.11 も、最後の dot 版(2024-01 リリースの `Winpython64-3.11.8.0dot.exe`)は .exe だけで、GitHub API の digest がない。上の 1〜3 を実装すれば、同じ方法で足せる。2026-10-06 の時点では、3.11 は足さないことにした。(確定)

## 2. WinPython のキャッシュを、リポジトリの外に置けるようにする

### 背景
- 今は、ダウンロードした WinPython の zip を、このリポジトリの `.build\downloads\` にキャッシュしている。2回目以降は SHA-256 が一致すればダウンロードしない。
- `.build\` は gitignore されている。別の PC に clone したときや、`.build\` を消したときは、ダウンロードし直すことになる。
- GitHub のリリースファイルは古いもの(2022〜2023 年)も残っているが、ずっと残るという保証はない。古い版(3.12 など)が取れなくなる恐れがある。

### 今のスクリプトのままでできること
- zip を別の場所(NAS など)に控えておき、`.build\downloads\` に同じファイル名で戻せば、ダウンロードせずに使う。ファイル名は URL の末尾と同じ。SHA-256 で照合するので、置いたファイルが正しいかも確かめられる。

### 対応
- 2026-10-06: コードは変えず、README の「WinPython のキャッシュ」に上の手順を書いた。(確定)

### 残っている案(未決定)
- 設定項目を足して、キャッシュの置き場所を指定できるようにする。例: `settings.local.json` に `"winPythonCacheDir": "D:\\odekake-cache"`。項目名と動作(保存先と読み込み先の両方に使うか、など)は未定。必要になったら検討する。
